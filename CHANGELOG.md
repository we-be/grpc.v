# Changelog

All notable changes to grpc.v are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/).

## Stability

grpc.v is pre-1.0 (**0.x**). The **wire behavior** — gRPC framing, the Connect
protocol, status-code mapping, and error details — is production-solid, proven
against grpc-go, connect-go, and the official Connect conformance suite, and is
not expected to change. The **V API surface** is still converging and may break
in any 0.x release. 1.0 waits for the native gRPC server (gated on upstream V
HTTP/2 response-trailer support) to prove the server API against real gRPC, not
only Connect.

## [Unreleased]

### Added
- **Native gRPC server** (`GrpcServer`): real gRPC over HTTP/2 — TLS via ALPN,
  or cleartext h2c on a plain listener — with 5-byte message framing and the
  terminal status in HTTP/2 trailers. Drives the same generated dispatch as
  `ConnectServer`, so one service is served over either transport unchanged.
  Proven against a real grpc-go client (v1.83.0) over h2c — unary and
  server-streaming: success bodies, Trailers-Only errors, a percent-encoded
  `grpc-message`, the status-code table, and leading vs trailing metadata all
  round-trip (`interop/grpc_run.sh`, `interop/goserver/grpcclient`).
- **Buffered streaming** (server- and client-streaming). A server-streaming rpc
  materializes its whole response into the body as multiple gRPC frames; a
  client-streaming rpc consumes the whole buffered request. Generated stubs
  return `Reply[[]Resp]` / take `[]Req`; the client gains
  `server_stream`/`client_stream` (with `RawStreamReply`), and the generated
  `<Name>Service` a `grpc_call` message-list dispatch. Needs **protobuf.v ≥ 1.3.0**.
- `percent_encode` for writing the `grpc-message` trailer (inverse of the
  existing `percent_decode`).

### Notes
- Requires a V toolchain with server-side HTTP/2 response trailers
  (vlang/v#28066): on master now, not yet in a tagged release (the 0.5.2 tag
  predates it). CI builds against master via `setup-v`'s `check-latest`, so it
  compiles there; users pinned to a `stable` V release need the next release.
- **Streaming is buffered, not incremental** — one POST each way, so it fits
  finite streams and inherits the server's 8 MiB request-body cap. True
  incremental delivery and **bidirectional** streaming need an upstream
  net.http streaming-handler API.

## [0.2.0] - 2026-08-10

### Added
- **Per-call options** (the Go-gRPC idiom): `client.rpc(req, grpc.timeout(d),
  grpc.header(k, v))`, with client-side deadline enforcement (surfaced as
  `deadline_exceeded`) and request/response metadata. Every generated stub
  returns `grpc.Reply[T]{ msg, metadata }`.
- **Server-side handler context** (`grpc.ServerContext`): handlers read request
  metadata and set response headers, trailers, and typed error details
  (`Status.details`). Connect unary trailers ride as `Trailer-`-prefixed
  response headers, so this works on V's HTTP/1.1 server today.
- **Official Connect conformance** wired into CI (`interop/conformance/`):
  Connect / unary / both codecs, 85/88 passing with the gaps enumerated in
  `known_failing.txt`. Runs on Linux; macos/arm64 is deferred pending an
  upstream V fix (`http.Server` corrupts request bytes under its request loop
  on arm64 — reproduced and isolated to the V stdlib, not grpc.v/json2).
- Frame-decoder fuzzing and adversarial server tests.

### Changed
- **Metadata is multi-valued on both sides** (`map[string][]string`) — HTTP
  metadata keys may repeat. `grpc.header()` now appends rather than replaces;
  `ServerContext` has `set_header`/`add_header` (and `_trailer`) plus `header()`
  (first value) and `headers()` (all). This resolves the earlier client/server
  asymmetry.
- Generated server glue threads a `mut ctx grpc.ServerContext` through the
  handler and dispatch — needs **protobuf.v ≥ 1.2.0** (1.2.1 recommended).

### Fixed
- Connect error-detail `value` is now unpadded base64 (the spec's
  `RawStdEncoding`); the code→HTTP status table matches connect-go exactly
  (`deadline_exceeded` → 504, `failed_precondition` → 400); an unrecognized
  procedure returns HTTP 404 (routing miss) with code `unimplemented`.
- A remote-DoS crash in the Connect JSON codec (a hostile bare-scalar/empty
  body panicking V's json2) — fixed upstream in protobuf.v 1.1.1, found by this
  repo's fuzzing.

## [0.1.0] - 2026-08-08

First release: a unary gRPC **client** (proven against grpc-go over TLS/HTTP-2)
and a Connect unary **server** (proto *and* JSON codecs, proven against
connect-go), with typed clients, handler interfaces, and dispatch generated by
protobuf.v's `vpbgen -grpc`. Includes the kvd etcd-lite dogfood over
vlang/leveldb.
